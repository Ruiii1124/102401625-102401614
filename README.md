## 一、项目简介

一个面向校园学生的失物招领 Web 应用，帮助同学们集中发布和查看寻物、招领信息，并通过物品名称等关键词快速搜索。主要流程为：

**发布信息 → 浏览/搜索 → 查看详情 → 联系发布者 → 更新状态**

技术栈：纯 HTML + CSS + 原生 JavaScript，数据存储在浏览器 `localStorage` 中，无需后端服务。

## 三、使用说明

### 3.1 运行网页

网页无需构建或安装 npm 依赖。推荐通过本地静态服务器访问，以保证各页面使用同一来源的 `localStorage`，并使复制功能在 localhost 安全上下文中运行。

任选一种方式：

- 已安装 Python：在项目根目录执行以下命令，再用 **Chrome 或 Edge**打开 `http://127.0.0.1:8000/index.html`。

  ```bash
  python -m http.server 8000 --bind 127.0.0.1
  ```

  保持终端运行，结束时按 `Ctrl+C`。这是静态文件服务器，不是业务后端。
- 使用 VS Code 的 **Live Server** 插件：右键 `index.html`，选择“Open with Live Server”。

也可直接打开 `index.html`，但 `file://` 下跨页面存储与剪贴板行为依浏览器而异，建议按上述 HTTP 方式验收。每次演示使用相同浏览器、地址和端口。

## 五、附加特点

1. **一键复制联系方式**：联系页点击按钮即可复制 QQ 号，避免手动输入出错。
2. **搜索历史记录**：搜索页自动保存最近 5 条搜索关键词，点击可快速重新搜索。
3. **状态闭环**：在“我的发布”中标记“已找到/已归还”后，重新打开首页、搜索结果、详情页可看到对应状态，详情页联系按钮自动禁用。进行中的寻物显示“寻找中”，招领显示“待认领”；完成的寻物显示“已找到”，招领显示“已归还”。“我的发布”按发布者区分，只显示当前浏览器用户发布的信息。
4. **空状态友好提示**：无数据、无搜索结果时给出明确提示，不会显示空白页面。
5. **分类图标**：不同物品分类显示不同 emoji 图标，提升可读性。
6. **地点组合筛选**：基于已有地点文本匹配，与关键词、类型、分类、状态同时筛选，空地点不限；结果页重新搜索保留筛选条件。

## 六、浏览器兼容性

- 推荐使用 **Chrome** 或 **Edge**（基于 Chromium 内核，渲染效果一致）。
- 使用 `localStorage` 存储数据，不同浏览器数据不互通，清除浏览器数据会清空已发布信息。

### localStorage 与发布者标识

- `campus_lost_found_items`：保存信息数组，包括 `ownerId` 和 `active/resolved` 状态。
- `campus_lost_found_owner_id`：首次访问生成并持续使用的当前浏览器标识；发布时写入信息，更新状态时校验相等。
- `campus_lost_found_search_history`：最近 5 条关键词。
- 旧信息缺少 `ownerId` 时保留原数据，仍可浏览和搜索，不自动认领；不会出现在“我的发布”，也不能更新状态。

## 七、已知限制

- 数据存储在浏览器 `localStorage` 中，换浏览器、换设备或清除浏览器数据后，信息不会同步，属于本地演示型项目。
- ownerId 区分浏览器本地发布者，不是身份认证。同一浏览器来源共享标识，用户仍可用开发者工具修改本地数据。
- 搜索历史写入失败的提示尚未处理；存储被禁用或额度耗尽时，保存关键词可能阻止搜索跳转，本轮仅补齐状态更新的保存失败反馈。
- 未实现后端服务、实名认证、即时聊天、地图定位等功能，符合本次作业范围要求。
